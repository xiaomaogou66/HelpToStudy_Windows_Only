# 🔄 多端同步：ics 后端 与 Google 后端（地位同等）

> 一条命令，两个后端，**读同一份配置、出同一份事件、用同一套 UID**：
>
> ```bash
> cd 05-日程安排/_脚本
> ./同步日程.bat                # 按配置跑（默认两个后端都跑）
> ./同步日程.bat --后端 ics      # 只写本机 .ics
> ./同步日程.bat --后端 gcal     # 只推 Google 日历
> ./同步日程.bat --dry-run      # 只看会同步什么（不写文件、不联网）
> ```

## 两个后端到底差在哪

| | **ics 后端**（`导出ics.py`） | **Google 后端**（`同步日历.bat`） |
|---|---|---|
| 输出 | 库内 `_资源/日程安排.ics` 一个文件 | Google 专用日历（服务账号 / OAuth） |
| 云依赖 | **零**（不需要账号、不需要代理） | 需要 Google 账号 + 凭据（+ 本机代理） |
| 手机/第二台电脑看 | 要自己把这个 .ics **送出去**：云盘同步 → 手机日历订阅；或让 iCal 插件写成 Gist → 手机订 URL | **原生同步**：同一 Google 账号，手机自带日历直接看到，秒级 |
| 双向修改 | 只读（手机上的改动不会回笔记） | 只读（脚本全量重建该窗口，手机上的改动会被覆盖） |
| 提醒 | 自带 VALARM（默认：任务 10 分钟前、课 20 分钟前） | 自带 reminders（同一份配置） |
| 适合 | 不装 Google、只想有个统一日历；离线/墙内机器 | 多端随手看、要手机到点弹提醒 |
| 命令 | `./同步日程.bat --后端 ics` | `./同步日程.bat --后端 gcal` |

**「地位同等」体现在**：
- 两边都是**完整后端**，谁都不依赖谁，谁也都可以单独用。
- `00-配置/同步配置.json` 里的窗口、时区、提醒分钟、已完成任务口径、课表源，**两个后端共用**（不会出现「ics 里 20 分钟、Google 里 10 分钟」这种不一致）。
- 事件的 UID 是同一套（`<笔记任务 uid>@obsidian-schedule`）：笔记里一条任务 ↔ 两种日历里同一条，不会重复。
- 想只留一个：把 `00-配置/规划配置.json` 的 `同步.后端` 改成 `["ics"]` 或 `["gcal"]`。

# 一、ics 后端怎么用起来（零配置）

跑一次就有了：

```bash
cd 05-日程安排/_脚本 && ./同步日程.bat --后端 ics
# ✅ 已写出 05-日程安排/_资源/日程安排.ics（250 条事件）
```

**怎么让手机也看到**（三选一）：

| 办法 | 做法 | 特点 |
|---|---|---|
| **A. 云盘同步**（推荐） | 把库（或 `_资源/日程安排.ics`）放进坚果云 / OneDrive / Syncthing，手机装对应 App | 不用公开任何东西；手机日历订阅本地文件（iOS「添加日历账户 → 其他 → 订阅」；Android 用 ICSx⁵ 等） |
| **B. Gist 订阅** | Obsidian 的 iCal 插件（本库已装）能定时把 .ics 写成 GitHub Gist，手机订那条 `raw` URL | 全自动；注意 Gist 是**公开**的，别把私密目标写进标题 |
| **C. 只在电脑看** | Obsidian 里用 iCal 插件 / 别的日历插件读这个文件 | 最省事 |

> 想换文件名/位置：改 `00-配置/规划配置.json` 的 `同步.ics输出`。
> 输出是**原子替换**的：订阅方永远读到完整文件，不会读到写一半的内容。

# 二、Google 后端：服务账号怎么配（多端同步用它）

## 先看清三个角色（否则后面每一步都会觉得莫名其妙）

| 角色 | 是谁 | 干什么 | 你要给它什么 |
|---|---|---|---|
| **你** | 你自己的 Google 账号 | 在手机/电脑上看日历、收到提醒 | —— |
| **服务账号** | Google 建的一个「机器人账号」，没有密码、只有密钥文件 | **替脚本写日历**（脚本不是人，登录不了人类账号） | 一个密钥文件（放库外） |
| **专用日历** | 你在 Google 日历里新建的一个日历 | 装「日程安排」同步过来的事件 | 共享给那个机器人（权限：更改事件） |

流程一句话：**脚本（用机器人的钥匙）→ 往专用日历写事件 → 你的账号能看到这个共享日历 → 手机自动同步。**
所以：**机器人和你的账号是两回事**，机器人只被授权动这一个日历，碰不到你的主日历和其它日历。

## 为什么推荐服务账号，而不是 OAuth

| | **方案 A · 服务账号**（推荐） | 方案 B · OAuth 桌面客户端 |
|---|---|---|
| 谁在替你动手 | 一个机器人账号，长期有效 | 你自己的账号，脚本拿"刷新令牌"替你操作 |
| Google Cloud 同意屏幕 / 发布 / 验证 | **完全不需要** | 必须「发布为正式」，还要填首页 + 隐私政策 + 授权域名 |
| 令牌过期 | 不过期（机器人密钥长期有效） | refresh token 长期不用会失效，要重新授权 |
| 多端 | 手机/电脑用**你自己的账号**看共享日历 | 一样 |
| 最小权限 | 只共享**一个专用日历**给它 | `calendar.app.created`，也是只管脚本自己建的日历 |

## 配置步骤（一次性，约 5 分钟）

### 第 1 步 · 建一个 Google Cloud 项目，并启用 Calendar API

- **在干什么**：给"机器人"开一间工作间（项目），并打开它唯一需要的能力（读写日历的 API）。
- **为什么**：服务账号必须住在某个项目里；并且 Google 默认**关闭** Calendar API——不启用的话，后面脚本一调用就报 `403 API not enabled`。
- **怎么做**：<https://console.cloud.google.com/> → 顶部新建项目（名字随意，如 `schedule-sync`）→ 左侧「API 和服务 → 库」→ 搜 `Google Calendar API` → **启用**。
- **做完你会看到**：项目切换器里出现该项目；Calendar API 页面显示「已启用 / 管理」。
- **跳过会怎样**：第 8 步 `./同步日历.bat --check` 报 `403 accessNotConfigured`。

### 第 2 步 · 创建一个服务账号

- **在干什么**：创建一个"机器人身份"——它有邮箱、有身份，但没有密码、不能登录网页。
- **为什么**：脚本要写日历就必须以某个身份调用 API。用你自己的账号需要 OAuth 同意屏幕（麻烦且会过期）；机器人身份则是长期有效的。
- **怎么做**：「API 和服务 → 凭据 → 创建凭据 → 服务账号」→ 名字随意（如 `schedule-bot`）→ 创建（角色/权限**不用给**）。
- **做完你会看到**：凭据列表里多出一个服务账号，并且它的邮箱形如
  `schedule-bot@<项目ID>.iam.gserviceaccount.com`。
- **下面会用到它**：第 5 步要拿这个邮箱去共享日历。**先复制记下来。**
- **跳过会怎样**：第 3 步没有密钥可下载。

### 第 3 步 · 下载这个机器人的密钥（JSON）

- **在干什么**：把机器人的"私钥文件"下载到本地——**这就是密码本身**。
- **为什么**：脚本运行时要用它证明"我就是那个机器人"。
- **怎么做**：进入刚建的服务账号 → 顶部「密钥」→「添加密钥 → 创建新密钥」→ 类型选 **JSON** → 创建（浏览器会自动下载一个长名字的 `.json`）。
- **做完你会看到**：下载目录里多一个 `.json`，打开能看到 `"type": "service_account"` 和 `private_key`。
- **⚠️ 安全**：这个文件等同于密码。**不要**放进 Obsidian 库、不要截图、不要发聊天、更不要提交到 GitHub。（下一步就把它挪到库外。）
- **跳过会怎样**：脚本找不到凭据，第 8 步报「找不到凭据文件」。

### 第 4 步 · 把密钥放到库外，并只给自己可读

- **在干什么**：把密钥从"下载目录"搬到库外的一个私人目录，并把权限收紧到只有你能读。
- **为什么**：库会被备份、同步、打包、甚至上传 GitHub——密钥放在库内，迟早会跟着外泄。放库外 + `600` 权限，等于把它从流水线上拿下来。
- **怎么做**：
  ```bash
  mkdir -p ~/.config/schedule-sync && chmod 700 ~/.config/schedule-sync
  mv ~/下载/<那个长名字>.json ~/.config/schedule-sync/service-account.json
  icacls <文件> /inheritance:r /grant:r "%USERNAME%:R"   rem 替代 chmod 600：~/.config/schedule-sync/service-account.json
  ```
- **做完你会看到**：`ls -l ~/.config/schedule-sync/` 显示 `-rw------- service-account.json`。
- **跳过会怎样**：密钥继续躺在库里；一旦整库上传或发给别人，别人就能往你的日历写东西。

### 第 5 步 · 在 Google 日历里新建一个**专用**日历

- **在干什么**：给这套系统划一块"专属黑板"，事件只写在这里。
- **为什么**：脚本每次同步会**清空窗口内的全部事件再重建**（这样才能正确处理改时间、删任务）。如果指向你的主日历，你手动记的真实日程会被清掉——脚本为此内置了拒绝操作主日历的保护，但前提是你**有一个专用日历**可用。
- **怎么做**：手机或网页版 Google 日历 → 左侧「其他日历 → ＋ → 创建新日历」→ 名字如 `日程安排 (Obsidian)` → 创建。
- **做完你会看到**：左侧多出这个日历（此刻还是空的）。
- **跳过会怎样**：没有可写目标；若强行指向主日历，脚本会直接拒绝并退出。

### 第 6 步 · 把这个日历**共享给机器人**（关键一步，最容易漏）

- **在干什么**：授权机器人来这块黑板上写字。
- **为什么**：机器人默认**什么都看不到**——包括你刚建的日历。不共享的话，脚本虽然身份合法，但访问这个日历会得到 `404 notFound`（Google 用 404 表示"看不见"）。
- **怎么做**：该日历 →「设置和共享 → 与特定用户或群组共享」→ 添加**第 2 步那个服务账号邮箱** → 权限选 **「更改事件」** → 发送。
- **为什么必须是「更改事件」**：只给「查看」的话，脚本能读不能写，同步时会报 `403 forbidden`；给「进行更改」才有写权限。「更改事件」= 增删改事件，不包含改日历设置或删日历。
- **做完你会看到**：共享列表里出现 `schedule-bot@...iam.gserviceaccount.com`，权限写着「更改事件」。
- **跳过/给错权限会怎样**：`404 notFound`（没共享）或 `403 Forbidden`（只有查看权）。这是这一步最常见的两个报错。

### 第 7 步 · 取日历 ID，填进配置

- **在干什么**：告诉脚本"要写的是**哪一个**日历"。
- **为什么**：日历名字可以重复、可以改；只有 ID 是唯一的。脚本按 ID 定位，才不会写错地方。
- **怎么做**：该日历 →「设置和共享 → 日历 ID」（形如 `xxxxx@group.calendar.google.com`）→ 填进
  `05-日程安排/00-配置/同步配置.json` 的 `calendar_id`。
- **不想手抄 ID**，也可以让脚本列出来：
  ```bash
  cd 05-日程安排/_脚本 && ./同步日历.bat --list-calendars
  # 输出：<日历 ID>  └─ 名称：… ｜权限：owner   ← 把第 1 列填进 calendar_id
  # 如果提示「一个都没有」= 第 6 步的共享还没生效/没做
  ```
- **做完你会看到**：`同步配置.json` 里 `calendar_id` 是一串以 `@group.calendar.google.com` 结尾的 ID。
- **跳过会怎样**：脚本会退回到"按名字找日历"，找不着就**新建一个**——于是你会有两个同名日历，事件分家。

### 第 8 步 · 告诉脚本密钥在哪（绝对路径）

- **在干什么**：把第 4 步那个库外路径写进配置，让脚本能找到钥匙。
- **为什么**：默认脚本只在 `_脚本/` 目录里找密钥；密钥已经搬到库外了，所以必须显式告诉它路径。
- **怎么做**：编辑 `05-日程安排/00-配置/同步配置.json`：
  ```jsonc
  {
    "calendar_id": "xxxxx@group.calendar.google.com",
    "credentials_file": "/home/你的用户名/.config/schedule-sync/service-account.json",
    "timezone": "Asia/Shanghai"
  }
  ```
- **注意**：必须是**绝对路径**（以 `/` 开头）。`~` 不会被展开。
- **做完你会看到**：这个 JSON 能正常解析（不有多余逗号）。
- **跳过会怎样**：第 9 步报「找不到凭据文件」。

### 第 9 步 · 先体检，再真同步

- **在干什么**：先验证"身份 + 目标日历"两件事都通，再真正写事件。
- **为什么**：把"授权问题"和"数据问题"分开排查——`--check` 只碰身份和日历，`--dry-run` 只算要推什么但不写。全绿了再真同步，出问题一眼就知道是哪一层。
- **怎么做**：
  ```bash
  cd 05-日程安排/_脚本
  ./同步日历.bat --check       # → ✅ 授权有效｜日历可用：日程安排 (Obsidian)
  ./同步日历.bat --dry-run     # → 列出要推的任务与课表条数（不联网写）
  ./同步日程.bat --后端 gcal    # 真正写入（或直接 ./同步日程.bat 两个后端一起）
  ```
- **做完你会看到**：`--check` 打印服务账号邮箱与日历名；真同步后 Google 日历里出现课表与任务（含提醒）。
- **跳过会怎样**：出了问题你得同时怀疑身份、日历、数据三层，排查时间翻倍。

### 第 10 步 · 手机/第二台电脑上让它显示出来

- **在干什么**：在你的设备上用**你自己的账号**订阅这个共享日历。
- **为什么**：同步是"写进 Google 日历"，能不能看到取决于该设备有没有显示这个日历——它不会自动出现在你的主日历里。
- **怎么做**：手机装 Google 日历 App → 登录**你自己的** Google 账号 → 左侧栏找到 `日程安排 (Obsidian)` → **勾选显示**（网页版同理）。第二台电脑浏览器打开 Google 日历同样勾选即可。
- **做完你会看到**：手机日历里出现课程与任务，到点弹提醒。
- **跳过会怎样**：网页版虽然在写，但你以为"没同步成功"。**看不到 ≠ 没写进去**，先检查这里。

> 之后要改提醒分钟、窗口天数、课表文件？改 `00-配置/同步配置.json`（两个后端共用）。
> 要改里程碑（倒计时）？改 `00-配置/规划配置.json`。

## 代理（墙内机器）

- **在干什么**：让脚本能连上 Google API。
- **为什么**：脚本固定走本机 `127.0.0.1:7897`（Clash Verge 默认口）；它**只对自己生效**，不动系统代理、不动你的 shell。
- **怎么做**：
  ```bash
  SYNC_PROXY=http://127.0.0.1:7890 ./同步日历.bat    # 换端口
  SYNC_PROXY=none ./同步日历.bat                     # 临时直连
  ```
- **做完你会看到**：脚本首行打印 `🌐 代理：…`。
- **不做会怎样**：报超时（`TimeoutError`），但 ics 后端完全不受影响。

## 凭据与安全清单（每一条都对应一个具体风险）

- 密钥文件放**库外**（`~/.config/schedule-sync/`）+ 权限 `600` → 防"整库打包/上传时连带外泄"。
- 绝不把密钥放进库里、更别 push 到 GitHub（仓库 `.gitignore` 已排除 `service-account*.json`、`calender-*.json`、`token.json`）。
- 只共享**一个专用日历**给机器人，权限「更改事件」→ 机器人碰不到你的主日历。
- 怀疑泄露（提交过、截图过、发过）：到 GCP「凭据 → 服务账号 → 密钥」**删除旧密钥**再新建，然后更新本地文件。**删密钥即失效**，比改密码快。
- 换机器：密钥文件**手带**过去（别走云盘公开链接），`同步配置.json` 在库里跟着走。

# 三、日常怎么用（最短路径）

| 场景 | 命令 |
|---|---|
| 周日写完周决策 | `./同步日程.bat`（两个后端一起，秒级） |
| 只想更新本机 .ics | `./同步日程.bat --后端 ics` |
| 只想推 Google | `./同步日程.bat --后端 gcal` |
| 检查 Google 凭据/日历 | `./同步日历.bat --check` |
| 换课表后 | 先 `/课表`，再 `./同步日程.bat` |
| 什么都不动只看结果 | `./同步日程.bat --dry-run` |
| 全层体检 | `./自检.bat`（不联网、不改数据） |

## 常见坑（症状 → 是哪一步出的问题）

| 症状 | 多半是 | 处理 |
|---|---|---|
| `403 API not enabled` | 第 1 步 | 去 Cloud 控制台启用 Google Calendar API |
| `404 / notFound` | 第 6 步 | 日历没共享给机器人（或共享了但还在生效中） |
| `403 / Forbidden` | 第 6 步 | 共享权限给成了「查看」，要改「更改事件」 |
| `找不到凭据文件` | 第 4 / 8 步 | 密钥不在库外指定路径，或 `credentials_file` 不是绝对路径 |
| `--list-calendars` 一个都没有 | 第 6 步 | 共享没生效 |
| 手机上看不到 | 第 10 步 | App 里该日历没勾选显示；或登录了别的账号 |
| 手机/电脑时间差一天 | 账号时区 | Google 账号设置里把时区改成 `Asia/Shanghai` |
| 约重复出现两次课程 | 中途改过日历 ID / 换过表 | 跑一次完整 `./同步日程.bat`（会全量对账重建） |
| 课表条数突然变 0 或减半 | 换表后解析失败 | 脚本默认**中止**不写；先 `--dry-run --ics 新表.ics` 体检，确认无误再加 `--allow-empty-ics` |
| ics 文件被订阅方读到半截 | —— | 不会：写 `.tmp` 再原子替换 |

## 相关

- 配置：`00-配置/规划配置.json`（后端开关/里程碑）· `00-配置/同步配置.json`（日历、课表、窗口）
- 规则：`00-配置/底线规则.json`（打卡项）
- 引擎：`_脚本/导出ics.py`（ics 后端）· `_脚本/sync_gcal.py` + `_脚本/同步日历.bat`（Google 后端）· `_脚本/同步日程.bat`（统一入口）· `_脚本/自检.bat`（体检）
- Google 后端更细的排错：`_脚本/README-首次配置.md`
